# test-sites

Локальные dummy-сайты на разных технологиях рендеринга и с разной
agent-readiness. Нужны, чтобы проверять краулер, извлечение фактов, генерацию
вопросов и аудит ботов.

## Запуск

```bash
npm start
```

Поднимает пять сайтов:

| Порт | Сайт | Технология | Что проверяет |
|---|---|---|---|
| 4101 | static | статический HTML | контент в сыром HTML, schema, sitemap, llms.txt |
| 4102 | spa | клиентский JS | контент только после fetch и рендера |
| 4103 | ssr | серверный рендер | контент в первом ответе, без JS |
| 4104 | hostile | JS + защита | robots запрещает AI-ботов, 403 для их UA |
| 4105 | agent-good | HTML + agent-стандарты | llms.txt, OpenAPI, MCP card, API catalog |

## Проверка

Во втором терминале:

```bash
npm run check
```

Печатает статусы для обычного UA и UA GPTBot, наличие фактов в сыром HTML,
блокировки в robots и статусы agent-эндпоинтов.

## Структура

```
serve.mjs              # пять HTTP-серверов без зависимостей
check.mjs              # проверка статусов и контента
sites/static/          # статический сайт
sites/agent-good/      # сайт с agent-стандартами
work/test-sites/       # user-spec
```

## Доверие для pi

Перед первым запуском `pi`: выполнить `pi`, затем `/trust`, либо запускать с
`--approve`. Без этого `pi` пропускает `.agents/skills/`.

## Ограничение

`check.mjs` не рендерит JS: он показывает, что SPA и hostile не отдают факты в
сыром HTML. Для проверки рендера нужен Playwright или Crawl4AI — это следующий
шаг, а не часть текущего каркаса.
